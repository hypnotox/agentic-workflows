# Plan: Default managed effort worktrees (ADR-0189)

## Goal

Implement ADR-0189: `awf effort new` creates one managed worktree per effort by default
(orchestrating the existing standalone `Manager.Add`), with `--no-worktree` and `--base`
flags, safety-constrained rollback, structured worktree and finish facts,
primary-root-qualified memory paths, a repaired Pi handoff root, and worktree-default
workflow/guide authority. Non-goals: no stored worktree attachment state, no binary
coordination lock, no runtime-specific session relocation, and no change to `show`/`list`
reply shapes.

## Architecture summary

Design rationale lives in ADR-0189; this plan only sequences it. The orchestration is a
new method on `internal/worktree.Manager` that calls `effort.Service.New`, then the
existing `Manager.Add`, and on Add failure rolls back through `effort.Service.Finish`,
consuming both the structured finish outcome (`FinishResult.Renamed`) and a new sentinel
error rather than error prose. `worktree.Result` gains structured `Path`/`Branch` facts,
landing in the same transaction as their first consumer, the `new` reply. The CLI layer
adds `--no-worktree`/`--base` to `awf effort new` and extends the text and `--json`
protocols, emitting every mutation line through the one `Result.String()` formatter.
`effort.Record.MemoryPath` becomes primary-root-qualified (absolute) whenever the
invoking checkout is not the primary root. The Pi handoff template resolves the primary
control root by dereferencing a linked worktree's `.git` file. Rendered authority
(workflow doc, working-with-awf, agent guides, checkpoint partials, glossary,
architecture) moves to worktree-default prose. ADR-0189's seven State-changes operations
apply in declaration order across three transactions: batch 1 (operations 1-4, Phase 2),
batch 2 (operations 5-6, Phase 3, travelling with the rendered-authority change that
makes them true), and the final batch (operation 7 plus the `Implemented` flip, landed by
the terminal-review transaction after the Phase 4 Pi repair).

- [ ] Task 1.5: Orchestration (`internal/worktree/manager.go`). Add:

  ```go
  // NewEffort publishes the effort residents, then creates its managed
  // worktree via the same standalone Add machinery (ADR-0189). On Add
  // failure it rolls back through restartable finish, removing the effort
  // only when the finish flow proves managed topology absent.
  func (m *Manager) NewEffort(title, base string) (effort.Record, Result, error)
  ```

  Behavior, in order:
  1. `record, err := m.efforts.New(title)`; on error, return it unchanged.
  2. `result, addErr := m.Add(record.Slug, base)`; on success, return
     `(record, result, nil)`.
  3. On `addErr`, attempt `finishResult, finishErr := m.efforts.Finish(record.Slug)`,
     then compose one error that wraps `addErr` with `%w`, branching on the structured
     outcome and the sentinel only (never on error strings). Exact message forms:
     - `finishErr == nil` (rollback complete):
       `worktree creation failed: <addErr>; effort <slug> rolled back; next action: fix the reported cause and retry 'awf effort new'`
     - `errors.Is(finishErr, effort.ErrManagedTopologyPresent)` (retain):
       `worktree creation failed: <addErr>; effort <slug> retained: managed topology remains; next action: inspect 'git worktree list --porcelain', clean up with native Git or 'awf effort worktree remove <slug>', then retry 'awf effort worktree add <slug>' or finish the effort`
     - `finishErr != nil && finishResult.Renamed` (interrupted mid-finish; the effort
       is tombstoned, no longer active):
       `worktree creation failed: <addErr>; effort <slug> rollback interrupted after rename: <finishErr>; next action: retry 'awf effort finish <slug>'`
     - Any other `finishErr` (retain, still active):
       `worktree creation failed: <addErr>; effort <slug> retained: rollback failed: <finishErr>; next action: resolve the rollback failure, then retry 'awf effort worktree add <slug>' or 'awf effort finish <slug>'`
     Render the quoted command names with backticks in the actual strings (the plan
     shows them with straight quotes only to keep this document's code spans intact).
  4. `--no-worktree` never reaches this method (the CLI keeps calling
     `effort.Service.New` directly for it).

  Tests in `internal/worktree/manager_test.go`, using the existing git fixture and
  injected `Runner`: (a) success returns the record plus a populated `Result`; (b) an
  injected `git worktree add` failure that creates no topology rolls back, and the
  effort directory is gone afterwards; (c) an injected failure that leaves topology
  behind (pre-create the managed path, as
  `TestAddFailureReportsActualTopologyAndPreservesEffort` does) retains the effort with
