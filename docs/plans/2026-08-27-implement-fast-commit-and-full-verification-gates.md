# Plan: Implement fast commit and full verification gates

## Goal

Replace the staged-suite-selecting repository gate with a fast hook-aware commit tier and an exhaustive terminal tier, add native Linux/amd64 and macOS/arm64 CI execution, publish only Linux and macOS artifacts, and align every shipped agent instruction and current-state claim. Broad mutation, platform emulation, and repeated full verification during iteration are non-goals.

## Architecture summary

`x` remains the single repository runner and owns two explicit modes: `./x gate` performs version validation, one native build, blocking lint including govet, and pin validation; `./x gate full` includes the commit checks plus complete native Go/coverage and Pi suites, advisory analysis, dead-code analysis, four Linux/macOS release cross-builds, and exact-range-qualified covercheck mutation. The old staged Go/Pi suite classifier is removed rather than retained as a parallel route. Hook and agent guidance discovers whether the corresponding hook is wired and never manually duplicates the same commit or push gate. Linux/amd64 CI owns exhaustive platform-independent assurance; a required macOS/arm64 dependency job runs only the complete native Go behavioral suite. Release configuration and platform-specific source retain Linux and Darwin only.

The complete implementation remains uncommitted in the managed worktree until the fast commit gate is operational, per the approved route. Focused commands prove each changed owner while iterating. Terminal full verification runs once against the complete staged candidate before the phase-closing commit, then the now-fast wired pre-commit hook checks that same candidate without repeating full assurance. Post-commit audit and implementation review use the immutable implementation range; ordinary focused settlement and terminal artifact commits remain legal and fast, with renewed full verification only when a correction invalidates the staged-candidate evidence.

## Definition of done

- `dod: fast-commit-boundary` `./x gate` contains only version validation, native build, blocking lint with vet analysis, and pin validation; its wired pre-commit invocation runs once and no staged path can select a behavioral suite.
- `dod: full-verification-boundary` `./x gate full` includes the commit checks plus complete native Go/coverage and Pi behavior, advisory analysis, dead code, four release cross-builds, and exact-range-qualified mutation, and terminal instructions run it once rather than as an iteration or routine phase loop.
- `dod: supported-platform-boundary` Required CI executes Linux/amd64 exhaustive assurance and macOS/arm64 native Go behavior for the exact revision, releases contain four Linux/macOS architecture artifacts, and no Windows implementation, test, artifact, or support claim remains active.
- `dod: hook-aware-guidance` Shipped agent, skill, workflow, testing, debugging, and release guidance prefers focused iteration commands, relies on wired commit/push hooks without manual duplication, and names manual fast or full execution only for absent hooks or distinct verification boundaries.
