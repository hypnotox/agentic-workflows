# Plan: First-class efforts and managed worktrees

## Goal

Implement [ADR-0164](../decisions/0164-lightweight-effort-records-and-independent-pi-telemetry.md): make lightweight efforts, optional memory, managed worktrees, and one-session-to-one-effort assignment binary-owned resources, while replacing Pi's lifecycle system with optional effort selection and independent session telemetry. Non-goals are automatic effort or worktree creation, multiple efforts per Pi session, automatic worktree deletion, event-sourced effort history, workflow enforcement, or rewriting legacy resident telemetry. The obsolete tracked `workflowTelemetry` block is removed by schema generation 20; generations 17-19 remain historical migration behavior.

## Architecture summary

The invoking checkout remains the source of tracked configuration and workflow bodies. A native-Git resolver derives the repository common directory and proves one primary worktree; only that primary worktree's confined `.awf/` directory owns repository-wide efforts, assignments, memory, worktrees, and metrics. The binary stores one atomically replaced JSON record per effort and one atomically replaced session-assignment map. Logical effort reads join the assignment map so assigned session IDs have one authority rather than a fallible multi-file duplicate.

The implementation lands reader and authority boundaries before removing old behavior. First add the common-root resolver and complete effort CLI, then native-Git managed worktrees, then current-state assignment. Replace protocol-2 lifecycle telemetry with a versioned session-stream reader/report model while retaining protocol-1 and protocol-2 resident ledgers read-only. Generalize generated resident-root preservation and documentation. Finally cut Pi over atomically: Pi invokes the effort CLI for explicit management, appends observations directly under a per-session lock, treats selection as optional context, and loads workflows without lifecycle mutation.

ADR-0164 operations are applied once in declaration order across the named phase transactions. For every batch, obtain the next repository-global sequence by running `./awf check` on the prepared ADR/current-state edits and using the sequence named by its diagnostic; never encode an authoring-time number. The exact event line is `- 2026-07-27: Applied; state-sequence: <checker-reported-next>; operations: <semicolon-separated exact declared operations>`. The first batch first appends the digest-bearing Implementing entry. The final batch appends all remaining operations and then the digest-bearing Implemented entry in the same commit, because Implementing may not have an empty Remaining partition.
