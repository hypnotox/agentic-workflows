# Plan: First-class efforts and managed worktrees

## Goal

Implement [ADR-0164](../decisions/0164-lightweight-effort-records-and-independent-pi-telemetry.md): make lightweight efforts, optional memory, managed worktrees, and one-session-to-one-effort assignment binary-owned resources, while replacing Pi's lifecycle system with optional effort selection and independent session telemetry. Non-goals are automatic effort or worktree creation, multiple efforts per Pi session, automatic worktree deletion, event-sourced effort history, workflow enforcement, rewriting legacy resident telemetry, or changing the still-authoritative `workflowTelemetry` configuration and schema-17 migration claims.

## Architecture summary

The invoking checkout remains the source of tracked configuration and workflow bodies. A native-Git resolver derives the repository common directory and proves one primary worktree; only that primary worktree's confined `.awf/` directory owns repository-wide efforts, assignments, memory, worktrees, and metrics. The binary stores one atomically replaced JSON record per effort and one atomically replaced session-assignment map. Logical effort reads join the assignment map so assigned session IDs have one authority rather than a fallible multi-file duplicate.

The implementation lands reader and authority boundaries before removing old behavior. First add the common-root resolver and complete effort CLI, then native-Git managed worktrees, then current-state assignment. Replace protocol-2 lifecycle telemetry with a versioned session-stream reader/report model while retaining old resident ledgers read-only. Generalize generated resident-root preservation and documentation. Finally cut Pi over atomically: Pi invokes the effort CLI for explicit management, appends observations directly under a per-session lock, treats selection as optional context, and loads workflows without lifecycle mutation. ADR-0164 operations are applied once in declaration order across the named phase transactions.

## Verification

- Primary and linked invocations use one confined resident root while reading tracked authority from the caller; hard path/ownership failures are never forceable.
- Effort creation defaults to memory and no worktree; worktree add/integrate/manual-record/remove obey exact ownership, cleanliness, ancestry, and force/reason policy; completion retains worktrees.
- One atomic assignment map gives each Pi session zero or one effort, supports reassignment at any time, and changes new-stream report joins without rewriting observations.
- New telemetry is session-keyed, versioned, append-only, idempotent, locked, fsynced, privacy-minimal, and contains no effort ID; malformed or incomplete state is preserved for repair. Legacy protocol-2 resident data remains byte-identical and read-only.
- Pi creates/selects efforts only on explicit `/awf-effort` commands; governed workflow entry and handoff work without an effort and never mutate lifecycle history.
- `./x render`, `./x check`, `./x pi-test run`, `go test ./...`, staged check, and `./x gate` pass at every phase; final `./x gate full` and code review finish cleanly.

## Notes

- The managed branch name is deliberately fixed to `awf/<effort-id>`; ADR-0164 authorizes explicit base selection but does not require a branch-name override.
- Existing protocol-2 telemetry remains readable as legacy historical data under its embedded effort identity. Only new session streams use current assignment joins; no migration or automatic cleanup crosses that boundary.
- The existing `workflowTelemetry` configuration and schema-17 migration claims are outside ADR-0164's declared operations and therefore remain compatible rather than being removed in this effort.
