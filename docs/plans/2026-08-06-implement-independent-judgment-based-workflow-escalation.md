# Plan: Implement Independent Judgment-Based Workflow Escalation

## Goal

Replace awf's bundled minimal-versus-non-trivial workflow chain with independently earned brainstorming, effort, grounding, ADR, plan, and implementation-review mechanisms; ship grounding as a reusable support skill and migrate compatible adopters safely. Preserve repository authority, artifact review, verification, commit gates, effort-state formats, existing runtime tools, and publication-safe rendering, without adding a classifier, policy schema, workflow router, checklist, or runtime mechanism.

## Architecture summary

One catalogued `grounding` support skill becomes the cross-target owner of fresh-context repository-premise checks and the existing grounding-checker pairing. The workflow document and affected skills state independent judgment triggers, while `effort-workflow` alone owns effort creation through finish and `reviewing-impl` owns assurance for either effort-backed or self-contained effort-free evidence. A schema-37 config migration adds standard grounding only to adopters using standard brainstorming and refuses a project-local grounding collision. Focused semantic tests pin those ownership and routing contracts across both targets, Pi's existing dedicated grounding tool, empty optional data, all four effort/review completion routes, and upgrade fixtures. One implementation transaction applies the interdependent templates, catalog, migration, current-state claims, ADR application events, generated outputs, and lock updates.

Before dispatch, the parent establishes a clean and green managed-worktree baseline: `git status --short` prints no output, `./x check` reports clean, and `./x gate` passes. The phase owner receives this verified baseline and works only in `/home/hypno/Projects/agentic-workflows/.awf/worktrees/proportional-workflow` until returning its completed report.
