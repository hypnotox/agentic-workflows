# Plan: Associate Pi sessions with efforts and live checkout context

## Goal

Implement [ADR-associate-pi-sessions-with-efforts-and-live-checkout-context](../decisions/associate-pi-sessions-with-efforts-and-live-checkout-context.md): give awf a bounded memory-metadata and advisory activity protocol, render an explicit Pi `using_effort` tool that rebinds the same session between validated checkout roles, and publish live effort context through Remote Pi without making presence authoritative. The plan also migrates new and structurally updated memories to closed YAML frontmatter and keeps legacy handoff identity compatible. Non-goals: no automatic effort selection or checkout following, no coordination lock, no lifecycle ledger, no direct TypeScript resident writes, no guessed receiving checkout, and no portable runtime claim before owner releases contain both prerequisites.

## Architecture summary

The effort package remains the policy and persistence owner. It gains a memory codec that separates identity-only compatibility from full metadata validation/update, and an optional protocol-1 `activity.json` codec with atomic owner-checked transitions. The composition root injects the clock and Git/control-root questions; `cmd/awf` owns nested grammar and JSON presentation. Existing show/list/finish behavior only admits the optional resident and checks memory identity, while `memory update` and `activity` deliberately perform the stronger parsing needed by their own operations.

The Pi adapter is a generated multi-file extension. `client.ts` owns bounded `./awf effort ... --json` invocation and closed reply decoding; `index.ts` owns the immutable in-process association snapshots, queued command, Pi `changeCwd` orchestration, heartbeat/shutdown lifecycle, and Remote Pi translation. A process-local `globalThis` transfer coordinator carries only a pending token and immutable plain-data snapshot across Pi's `session_shutdown(reason="cwd")` runtime replacement; it is consumed by the destination extension instance and cannot survive a process restart. Activity is committed only after live rebinding. Remote publication is always regenerated from the latest binary reply and atomically replaces the `awf` namespace.

State changes apply in three checked batches. The first implementation batch makes the effort/CLI/memory and dual-format handoff claims true. The second makes the generated-output and effort-session-association claims true while preserving mandatory capability degradation. The final batch raises the tested runtime floor and real-runtime smoke only after published immutable owner artifacts contain Pi commit `f9447485497b12c100c2064c295c2c1beead0c29` and Remote Pi commit `3355463ff484bbd4fb80ada9fcd826dcb6ad6a53`; it then co-flips the ADR and plan to `Implemented`. If those releases do not yet exist, Phase 3 is a legal green stopping point with the ADR `Implementing` and the final two operations Remaining.
