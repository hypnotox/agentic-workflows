# Plan: Associate Pi sessions with efforts and live checkout context

## Goal

Implement [ADR-associate-pi-sessions-with-efforts-and-live-checkout-context](../decisions/associate-pi-sessions-with-efforts-and-live-checkout-context.md): give awf a bounded memory-metadata and advisory activity protocol, make core `effort-workflow` the one cross-target selection for using the exact awf-managed worktree, derive an explicit Pi-only `using_effort` tool and skill that rebind the same session between validated checkout roles, and publish live effort context through Remote Pi without making presence authoritative. The plan also migrates new and structurally updated memories to closed YAML frontmatter and keeps legacy handoff identity compatible. Non-goals: no automatic effort selection or checkout following, no coordination lock, no lifecycle ledger, no direct TypeScript resident writes, no guessed receiving checkout, no parallel harness-owned worktree, no Pi tool knowledge in non-Pi output, and no portable runtime claim before owner releases contain both prerequisites.

## Architecture summary

The effort package remains the policy and persistence owner. It gains a memory codec that separates identity-only compatibility from full metadata validation/update, and an optional protocol-1 `activity.json` codec with atomic owner-checked transitions. The composition root injects the clock and Git/control-root questions; `cmd/awf` owns nested grammar and JSON presentation. Existing show/list/finish behavior only admits the optional resident and checks memory identity, while `memory update` and `activity` deliberately perform the stronger parsing needed by their own operations.

The Pi adapter is a generated multi-file extension. `client.ts` owns bounded `./awf effort ... --json` invocation and closed reply decoding; `index.ts` owns the immutable in-process association snapshots, queued command, Pi `changeCwd` orchestration, heartbeat/shutdown lifecycle, and Remote Pi translation. A process-local `globalThis` transfer coordinator carries only a pending token and immutable plain-data snapshot across Pi's `session_shutdown(reason="cwd")` runtime replacement; it is consumed by the destination extension instance and cannot survive a process restart. Activity is committed only after live rebinding. Remote publication is always regenerated from the latest binary reply and atomically replaces the `awf` namespace.

`effort-workflow` is a normal core catalog skill and the only configuration selection. New scaffolds select it through existing core semantics; upgrades do not mutate existing selections. Each enabled target renders its target-neutral skill. The Pi descriptor additionally declares the `using-effort` skill and `awf-effort` extension as target-owned outputs gated by that same selected skill. A bounded target-output path mode derives the Pi skill path from the configured prefix, and one shared predicate controls output planning, rendering, drift, and pruning. Non-Pi targets never declare either Pi output and use only native tooling to enter the existing awf-managed worktree. The general skill composes the workflow document and shared checkpoint partials, which remain the single lifecycle-policy home.

State changes apply in three checked batches. The first implementation batch makes the effort/CLI/memory, dual-format handoff, and checkpoint-guidance claims true. The second makes the selection-aware generated-output, cross-target effort-workflow, Pi-only skill, and effort-session-association claims true while preserving mandatory capability degradation. The final batch raises the tested runtime floor and real-runtime smoke only after published immutable owner artifacts contain Pi commit `f9447485497b12c100c2064c295c2c1beead0c29` and Remote Pi commit `3355463ff484bbd4fb80ada9fcd826dcb6ad6a53`; it then co-flips the ADR and plan to `Implemented`. If those releases do not yet exist, Phase 3 is a legal green stopping point with the ADR `Implementing` and the final two operations Remaining.
