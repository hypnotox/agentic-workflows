# ADR-0319: Adopt the Pi Cockpit Effort Integration Contract


## Context

awf's generated Pi effort extension publishes effort association and optional display suffixes through an external event contract. ADR-0231 established that contract under the former Remote Pi identity: awf-owned structural types describe `remote-pi:*` metadata, capability, suffix, and replay events without importing the provider package. The contract deliberately keeps effort association advisory and independent from routing identity.

The maintained provider has adopted the Pi Cockpit product identity through a hard cutover with no legacy event aliases. Its consumer now uses `pi-cockpit:*`, while released awf 0.41.0 still renders `RemotePi*` types and emits or listens on `remote-pi:*`. This is an active runtime mismatch, not historical wording: metadata, capability negotiation, and display-suffix publication no longer meet at the same event surface.

The generated extension is fixed catalog output. An adopter cannot override these literals through supported configuration or convention parts, and a direct edit violates render and drift authority. The correction therefore belongs in awf's template contract and release rather than in adopter-local output. Payload shapes, capability validation, replay, explicit clearing, graceful degradation, and the non-routing nature of presentation remain valid and must not change with the product name.

## Decision

1. `decision: pi-cockpit-event-identity` Adopt the Pi Cockpit event identity for awf's generated effort integration. The metadata, capability, display-suffix, and replay event families use the `pi-cockpit:*` namespace, and awf-owned structural type terminology uses `PiCockpit` rather than `RemotePi`.
2. `decision: hard-contract-cutover` Replace the former event and type identity without compatibility aliases, dual publication, or fallback listeners. One generated contract prevents ambiguous capability state and completes the provider's approved hard cutover.

## Consequences

Generated Pi adopters and Pi Cockpit share one coherent event identity, so effort metadata and optional suffix negotiation work after the provider cutover. This is an identity-only change: the structural boundary remains dependency-free and retains all authorization, lifecycle, routing, payload, capability, replay, clearing, and failure semantics established by ADR-0231.

The change is intentionally incompatible with providers that expose only the former Remote Pi events. Adopters must upgrade awf and the provider together; awf does not bridge mixed versions. A new awf release is required because permanent lock authority must identify the template and generated bytes reproducibly.

The rename touches the template, generated dogfood output, structural tests, publisher assertions, current-state provenance, and adopter-facing changelog together. It does not govern the Pi Cockpit repository's implementation or release policy.

## Alternatives Considered

| Alternative | Why not chosen |
|---|---|
| Retain `remote-pi:*` as a generic historical protocol name | The names are active product identity, and the provider's hard cutover no longer consumes them. |
| Publish and listen on both namespaces temporarily | Dual capability and suffix state would create lasting compatibility behavior explicitly excluded by the approved cutover. |
| Add an adopter-configurable event prefix | The integration has one provider contract; configuration would distribute external protocol selection into every adopter without a second supported provider. |
| Hand-edit the adopter's generated extension | The edit would violate template ownership, permanent lock authority, and drift reproducibility. |
