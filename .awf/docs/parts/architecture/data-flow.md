Commands construct one immutable `project.Session` through `Loader` for the selected working, candidate, staged, synthetic, or non-repository universe, then pass that Session through one focused operation before rendering its result or mapping its error. Mutating commands compose focused operations that acquire their selected writer lease, open confined authority access, and reload a fresh committed Session before a single synchronization attempt. Each Session binds selected configuration to complete current facts and carries the matching roots, Git and reader handles, and artifact-registry projection. `internal/currentstatecoord` constructs staged Sessions through the same Loader path and invokes the existing semantic owners. Focused topic reads consume the working authority corpus; path resolution combines that corpus with the working inventory, while its uncovered form reports paths outside configured domain territory. One single-use Publisher operation registers complete output definitions, settles collision and coalescing policy, renders each accepted node once, and supplies the same immutable plan to drift, generated-output checks, and publication. Mutations acquire their writer lease before mutable-authority reads, strictly parse live authority, completely preflight every collision and destructive path they can derive, protect paths without sufficient ownership evidence, and publish the lock last. Init's pre-prompt collision probe projects only definition paths and never executes a second authoritative render pass. `.awf/awf.lock` records the completed render state. Working and staged checks load separate authority snapshots; audit reads selected history through `internal/git`. Git-backed multi-file mutation is ordered rather than transactional: the first failed mutation stops processing, earlier successful effects remain visible, and reported affected paths guide inspection and rerun. Effort residents remain local and unmanaged by rendering.

The dependency direction is `cmd/awf` to focused application operations, then to immutable project state and domain services, and from those operations and services to the semantic Git, snapshot, filesystem, publication, and rendering mechanisms they need. Command code parses, composes, invokes, renders owner-produced results, selects streams, and maps exits. State, domain, and mechanism owners do not depend back on application or command coordination. The [dependency-composition topic](topics/code-design/dependency-composition.md) owns the detailed extraction owners, forbidden reverse edges, and boundary values.
