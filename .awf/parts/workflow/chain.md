On Pi, the canonical chain is entered through the single discoverable `awf-workflow` router rather than individually discoverable governed skills. Invoke `awf_workflow` alone with the semantic skill name. Catalog metadata separately declares each workflow's entry target, legal entry predecessors, legal continuation phases, and attribution or route effects. The enforcing loader resolves explicit effort identity, validates the current frontier and route, plans a phase start, transactional transition, or continuation, and only after durable acknowledgement returns the fixed pre-rendered body from `.pi/awf-workflows/`. Continuation preserves the already-open phase start while replacing or clearing workflow, activity, and implementation-mode attribution; it never manufactures a same-phase transition. Chain successors use the same router, and retrospective completion is settled mechanically after a successful run. An agent continuing a normalized external checkpoint with no resident effort calls exclusive `awf_adopt_effort` with its explicit memory path, effort, route, phase, and semantic workflow; the runtime validates confinement, identity uniqueness, and catalog compatibility, atomically adopts the boundary, persists association, and only then returns the fixed body. Existing resident efforts use structured resume and are never re-adopted. A material blocker with its own outcome calls exclusive `awf_detour` with an explicit child effort ID and brainstorming workflow. The runtime durably creates and associates the derived child without changing the parent's open phase, then completion or abandonment settles one deterministic parent association and child return marker before restoring the parent selection; a failed return leaves the terminal child selected for startup recovery. Reviewer agents remain separately discoverable, while non-Pi targets keep their ordinary target-native skills.

The Pi dashboard shows `[awf:init]` while its bounded in-memory provisional window is unresolved, applies `[awf:<phase>]`, `[awf:done]`, or `[awf:abandoned]` immediately after validated local lifecycle appends, and asynchronously accepts only generation-current canonical metrics-then-doctor refreshes. Its muted below-editor totals come from unique active-branch assistant usage plus public current-context usage, while agent-facing metrics and doctor results are bounded allowlist-only summaries and full canonical detail stays in the dashboard, so workflow instructions must not add separate accounting calls or infer subscription or automatic-context state.
