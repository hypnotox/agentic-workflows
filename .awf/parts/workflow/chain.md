## Workflow

Use any enabled native skill when its purpose fits. Evaluate brainstorming, continuity/effort, grounding, ADR, plan, and implementation-review need independently at intake, then re-evaluate only affected triggers when material facts change. Brainstorming fires for material choices or clarification; effort creation fires only when durable continuity materially helps; grounding fires for broad or uncertain repository premises; ADRs fire for load-bearing choices or changed active claims; plans fire when sequencing, coordination, or resumability materially helps. A plan records and operationalizes approved choices rather than inventing speculative structure, checks, or work; implementation review fires when independent assurance has value and uncertainty resolves toward review. Universal repository authority, documentation, verification, and commit obligations apply regardless of which mechanisms fire.

`effort-workflow` alone owns continuity confirmation and effort creation through checkpoints, integration, divergence handling, pending artifact closure, managed-topology removal, retrospective routing, and finish. Work without continuity need carries no effort or memory. Existing efforts resume under fixed identity only inside the confirmed outcome, with one user-managed writer and report-only children. `reviewing-impl` owns assurance only and returns effort-backed work to `effort-workflow`; effort-free work concludes after review settles or after a justified low-risk skip. Divergent integration activates review before topology removal. No line count, artifact type, bundled work label, classifier, checklist, router, or new runtime mechanism selects the workflow.
